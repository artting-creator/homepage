Git 常用指令備忘

搭配同資料夾的 git-menu.bat 使用；選單裡的每個選項就是下面這些指令。

先搞懂這四個地方

Git 的指令幾乎都在搬動這四個位置之間的檔案，看懂這張圖，指令就不用背。

工作區
你正在編輯的檔案→ add → 暫存區
挑好要提交的→ commit → 本機倉庫
存成版本→ push → GitHub
雲端備份
git status -sb
看檔案現在在哪個階段。不確定的時候先打這個，它幾乎都會告訴你下一步該做什麼。

每天就這五個

90% 的日常操作。

git status -sb
哪些檔案改了、有沒有還沒推上去的提交。
git add -A
把所有變動（含新增與刪除）放進暫存區，準備提交。
git commit -m "說明文字"
存成一個版本。訊息寫「改了什麼」，之後找版本時全靠它。
git push
上傳到 GitHub。沒 push 就只存在這台電腦，電腦壞了就沒了。
git pull
把遠端的更新抓下來。換電腦或多台機器工作時，動手前先 pull。

看清楚改了什麼

提交前確認一下，可以避免把不該進去的東西一起提交。

git diff
逐行看還沒 add 的修改。畫面停住時按 空白鍵翻頁、q 離開。
git diff --stat
只看「哪幾個檔案、各改幾行」的摘要，適合快速掃一眼。
git diff --cached
看已經 add 進暫存區的內容。add 完才想確認時用這個。
git log --oneline --graph -20
最近 20 筆提交，一行一筆（只顯示標題）。
git log -10
最近 10 筆提交，完整顯示所有說明與內文。
git show --stat 代號
看指定提交的詳細說明內文與修改檔案統計（代號可用 HEAD 代表最新版）。
git show 代號
看指定提交的詳細說明 + 逐行程式碼差異 (diff)。

出事了怎麼救

依「損失由小到大」排列，先試上面的。

git restore 檔名
單一檔案改壞了，還原成上次提交的樣子。改到一半的內容會消失。
git restore --staged 檔名
不小心 add 錯檔案，把它退出暫存區。檔案內容不會變動，很安全。
git commit --amend -m "新訊息"
改掉剛剛那次提交的訊息或內容。只在還沒 push 之前用。
git reset --soft HEAD~1
撤銷最後一次提交，但修改全部保留。提交錯了想重來時用這個。
git reflog
你做過的每個動作紀錄。連 reset 掉的提交都找得回來，救命用。
git reset --hard
捨棄所有已追蹤檔案的修改。未追蹤的新檔案（??）不受影響。
reset --hard 沒有反悔的機會。它清掉的是「還沒提交」的內容，這些從來沒進過 Git，所以連 reflog 都救不回來。不確定的話，先用 git stash 把修改暫時收起來，比直接砍掉安全得多。

回頭取舊版本

想試試舊的做法、或把某個檔案退回幾天前的樣子。不必開分支。

git log --oneline -20
先找到目標版本的代號。開頭那串英數字就是，前 7 碼就夠用。
git show 代號:路徑/檔名
只看舊版長什麼樣，不動到任何檔案。最安全的第一步。
git diff 代號 -- 路徑/檔名
比對現在和那個版本差在哪，決定要不要換過去。
git checkout 代號 -- 路徑/檔名
把指定檔案退回那個版本，其它檔案完全不受影響。這就是切換新舊做法的方法。
git checkout HEAD -- 路徑/檔名
把檔案改回「最後一次提交」的樣子，也就是取消上一行的動作。
關鍵是先 commit 再切換。只要目前的版本已經提交（最好也 push 了），來回切換都是可逆的——新舊兩邊都躺在歷史裡，隨時拿得回來。反過來說，工作區還有沒提交的修改時去 checkout，那些修改會被直接蓋掉，而且救不回來。
實例：做了一個實驗版，測完想比較新舊哪個好。
git add -A git commit -m "實驗：改用新做法" # 先存起來，這樣才回得來 git push # 推上去更保險 git checkout HEAD~1 -- 檔案A 檔案B # 這兩個檔案退回上一版，去測舊做法 git checkout HEAD -- 檔案A 檔案B # 測完切回實驗版
什麼時候才需要開分支？當兩條線要長期並行、各自都會繼續提交的時候。像上面這種「試一下、比較完就決定留哪個」，commit 加 checkout 檔案就夠了，開分支反而多一層要管理的東西。

整個專案回到舊版本

不是只有幾個檔案，而是想看看「那天的專案整體長什麼樣」。

git checkout 代號
整個工作區變成那個版本。會跳出一大段 detached HEAD 的警告，那是正常的，不是出錯。
git switch -
回到剛才所在的地方。忘記自己從哪來的話，用 git switch master。
這個狀態下不要提交。detached HEAD 意思是「你不在任何分支上」，在這裡做的提交不屬於任何分支，切走之後就很難找回來。這個模式是拿來看的，不是拿來改的——真的想從舊版本繼續開發，要先 git switch -c 新分支名 幫它安一個家。

暫時收起來（stash）

改到一半但想先做別的事，又不想留下半成品的提交。

git stash
把目前的修改收進暫存櫃，工作區恢復乾淨。
git stash pop
把剛收起來的修改拿回來繼續改。
git stash list
看暫存櫃裡有幾筆，避免收了忘記拿。

Windows 的換行警告

每次 add 都跳出一整排 LF will be replaced by CRLF 的解法。

原因是 Windows 用 CRLF 換行、Git 內部存 LF，設定沒講清楚時 Git 每次都會提醒你一遍。 解法是在專案根目錄放一個 .gitattributes，把規則寫死在專案裡，就不會受各台電腦的設定影響：
* text=auto eol=lf *.bat text eol=crlf *.cmd text eol=crlf *.png binary *.jpg binary *.webp binary *.ico binary *.woff2 binary
放進去還不會馬上安靜 —— 警告會先反過來變成 CRLF will be replaced by LF，要讓工作區重新套用規則後才會歸零。建檔後跑一次下面這串，之後就不再出現：
git add .gitattributes && git commit -m "加入換行規則" && git rm --cached -r -q . && git reset --hard
執行前先確認 git status 是乾淨的（沒有未提交的修改），因為最後那段 reset --hard 會把工作區重新檢出一次。.bat 檔會被自動轉回 CRLF，這是 Windows 批次檔正常執行的必要條件。

第一次設定

新電腦或新專案才需要，設定過就不用再做。

git config --global user.name "你的名字"
提交時記錄的作者名稱。
git config --global user.email "你的信箱"
要跟 GitHub 帳號的信箱一致，貢獻紀錄才會正確歸戶。
git init
把現有資料夾變成 Git 專案。
git clone 網址
把 GitHub 上的專案抓到本機。
git remote -v
確認這個專案推去哪個 GitHub 倉庫。
